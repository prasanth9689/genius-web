# Genius Jobs

Genius Jobs is an open-source, frontend-only job search experience built with React and Vite. Its primary screen pairs a searchable job inbox with persistent, shareable job details. All listings and employer names are fictional demo content; applications and preferences remain in browser storage and are not sent to employers.

## Requirements

- Node.js 20.19+ or 22.12+
- npm

## Getting started

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. The app uses browser history routing; the Vite development server handles direct navigation to client routes.

## Commands

```sh
npm run dev       # start the development server
npm run build     # create a production bundle in dist/
npm run preview   # preview the production bundle
npm run lint      # run ESLint
npm test          # run focused service tests
```

## Product areas

- `/` — public landing page
- `/dashboard` — candidate workspace
- `/jobs` and `/jobs/:jobSlug` — filterable, URL-synced job inbox and details
- `/recommended`, `/saved-jobs`, `/applications`, `/job-alerts`
- `/companies` and `/companies/:companySlug`
- `/profile`, `/profile/resume`, `/settings`
- `/login` and `/register` — non-authenticating demo screens

## Architecture

- `src/data/jobs.js` contains deterministic fictional job, employer, and candidate data.
- `src/services.js` centralizes local filtering, recommendations, formatting, and browser storage.
- `src/App.jsx` contains the route shell and reusable page/job interactions.
- `src/App.css` and `src/index.css` define the responsive interface and theme tokens.

The job route is the source of truth for selected-job state. Query filters stay in the URL, so browser history can restore search and selected roles. Saved jobs, applications, profile details, alerts, and theme preferences use `localStorage`.

## Data model and future backend

Job records have stable IDs and slugs and include employer, location, work mode, employment type, experience, salary visibility, skills, posting date, and role details. `getJobs`, `getJobBySlug`, and `getRecommendations` in `src/services.js` form a seam for replacing local data with an API service. A future backend can add authenticated candidate APIs, employer publishing, search indexing, Redis-backed notifications, and secure resume upload without treating this demo as a production service.

Recommendation scores are transparent demo math: skill overlap 45%, title preference 25%, location preference 20%, and experience fit 10%. They are not generated by AI.

## SEO and deployment

This client-rendered demo sets a safe `noindex, nofollow` directive and does not emit JobPosting structured data for fictional listings. Public job SEO at scale should use prerendering, server-side rendering, or another crawler-friendly rendering strategy with verified live-job metadata. Configure the production host to serve `index.html` for client routes.

## Configuration

Copy `.env.example` to `.env.local` for local configuration. The frontend does not require API credentials or an external service.
